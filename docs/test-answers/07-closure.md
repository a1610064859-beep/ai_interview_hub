# 样本 07｜故障闭环实践者

虚构背景：参与过校园低速无人车测试，擅长复现、定位与回归，但高速量产经验有限。

## Q1 主回答

我是智能网联专业学生，负责过校园低速无人车项目的测试记录与问题闭环。一次路口锥桶被雨伞遮挡，目标框连续丢失，我把相机帧、检测结果和控制日志按时间对齐，补充了遮挡等级用例，修复后再用原场景回归。我想做智驾测试，因为“发现问题”只是第一步，能复现、解释并验证安全改进才有价值。

## Q2 主回答

我会把争论转成可核验的实验：固定版本、地图、速度、天气和触发动作，保存原始日志与视频，记录尝试次数及出现次数。对不易复现的缺陷，检查是否与时序、传感器状态或温度有关，必要时用日志回放或故障注入缩小条件。与开发共同确认判定标准，直到根因、修复提交和回归结果都记录在同一缺陷单中；未排除安全风险不直接关闭。

## Q3 主回答

我们没有完整汽车级 HIL，但做过控制器接入模拟环境的实验：用可重复的虚拟障碍物与信号延迟测试状态切换。这类台架适合边界输入、故障注入和大量回归。实车则检验真实传感器受天气、遮挡、路面以及其他交通参与者影响后的整车表现。台架帮助定位因果，实车验证真实 ODD 下是否仍安全；两边用同一场景编号互相追溯。

## Q4 主回答

我先确认安全员已稳定车辆，保留接管前后至少一段完整窗口，记录接管原因与触发时刻。排查分四层：传感器原始数据和目标检测有无漏检或跳变；融合目标与定位有无漂移；规划轨迹是否突然改变；控制请求与转向、制动实际反馈是否一致。所有记录按统一时间轴对齐，先找首个偏离预期的节点，再提出可在回放或台架验证的假设。

## Q5 主回答

暴雨可能造成相机水滴遮挡和激光雷达近场散射，毫米波雷达会出现多径或地杂波虚警；雾天视觉对比度和激光回波质量下降；夜间眩光会使相机过曝或目标置信度波动。融合层最值得看的是目标从一个传感器转到另一个时是否突然消失、重复或位置跳变。测试时按场景标签分别统计误检、漏检和跟踪中断，不用总体准确率掩盖高风险片段。

## Q6 主回答

我会先把版本标记为存在未关闭的转向安全风险，暂停该场景的放行签字。保留 CAN 转角请求与反馈、规划轨迹、定位和环境数据；检查超调是轨迹突变、控制参数还是执行器响应造成。让开发和安全负责人参与风险评审，明确复现范围、严重度、临时控制措施和修复后回归标准。即便频率低，只要潜在后果严重、根因不明，就不能以概率口头判断放行。

## 追问补充素材

- Q1：项目车为低速校园场景，我不会把它等同于高速量产经验。
- Q2：缺陷单应留原始附件、复现配置、修复版本和回归记录。
- Q3：台架覆盖可控边界，实车覆盖建模不充分的真实交互。
- Q4：先找时间轴上最早异常，再验证其是否能解释接管。
- Q5：目标连续性和跟踪稳定性比单帧识别结果更关键。
- Q6：应由有授权的评审机制决定准出，测试负责人的意见需书面留痕。
