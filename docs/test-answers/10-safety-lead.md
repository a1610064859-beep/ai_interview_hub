# 样本 10｜审慎的优秀测试负责人

虚构背景：能清楚区分事实、假设与决策权限；技术分析完整，但不夸大自己拥有的结果。

## Q1 主回答

我是智能车辆工程方向学生，参与过智驾原型系统的 HIL 与封闭场地联合验证。我的主要工作是把需求中的接管条件转为可观察的状态位和测试用例，记录 CAN/以太网日志，并组织失败用例复测。在一次目标短暂丢失场景中，我们最初只看到车辆减速，后来对齐目标列表和规划状态才发现系统在两帧之间切换了策略。我想做这个岗位，是因为测试的职责不仅是找出异常，更是明确风险边界、推动修复并留下可审计证据。

## Q2 主回答

我会先承认“目前不可稳定复现”是事实，但它不等于“故障不存在”。立即固定版本、标定、地图、车辆状态和 ODD 条件，保存原始日志与视频，标记事件前后统一时间窗口。随后与开发一起提出可能触发条件，分别用离线回放、HIL 注入和受控道路测试证伪，记录每种条件的尝试次数和结果。若潜在后果严重，缺陷保持打开并升级评审；关闭必须有可信根因、修复版本和覆盖原场景及邻近边界的回归证据。

## Q3 主回答

HIL 的价值是可控、可重复、可安全施加危险输入：例如传感器失联、总线拥塞或转向反馈异常，重点验证控制器状态机、降级和响应时序。实车道路测试检验真实传感器物理退化、道路附着、交通参与者和驾驶员接管，重点是指定 ODD 内的整车行为。我的做法是让需求、场景 ID、数据记录和缺陷编号贯通两端：台架发现机制问题，封闭场地检查整车后果，获批后再做道路验证。不能把模拟环境通过率直接当作实车安全证明。

## Q4 主回答

先由安全员稳定车辆并遵循路测处置规程，随后锁定事件的原始数据与时钟基准。我会核对接管触发源、驾驶员输入和系统状态位；再沿链路查看传感器原始帧与点云、融合目标、定位、规划轨迹、横向控制请求、底盘转角反馈以及车速和横摆率。若感知目标先跳变，再引发规划曲率变化，这是候选因果链；若规划请求平稳而实际转角突变，则优先核查执行链。初步 RCA 明确“已观测”“可复现”和“尚未证实”，并给出下一步验证实验。

## Q5 主回答

暴雨可能让相机镜头积水、激光雷达近场雨滴回波增多且有效距离下降，毫米波雷达也可能因路面多径产生虚警；大雾降低视觉对比度与激光回波质量；夜间强眩光会导致相机过曝和目标置信度抖动。融合风险不只是单帧漏检，还包括错误关联、目标 ID 切换、轨迹跳变与置信度过高，最终可能造成误刹或错误转向。我会按天气强度、距离、目标类型与相对速度分层，核对原始传感器、融合结果和车辆动作，并单独分析最危险的漏检及误检片段。

## Q6 主回答

我不会签署该版本的放行，因为高速匝道急转向的潜在后果严重，而且当前只有一次事件、没有可信根因，无法证明风险受控。先停止相关高风险路测，保存版本、场景、CAN/以太网、感知、规划、控制和底盘同步记录；当天升级给项目、功能安全、开发与测试负责人。用轨迹曲率、转向请求和实际反馈区分规划、控制或执行问题，在台架和封闭场地验证修复，并扩展到相邻速度、道路曲率和低附着条件。只有完成根因分析、修复、回归和正式准出评审后才恢复放行；如时间不够，应延期或限制功能适用范围，并清楚记录残余风险和责任人。

## 追问补充素材

- Q1：我的证据链包含需求、场景、原始日志、缺陷、修复与回归结果。
- Q2：偶发率只是观测结果；危险程度和暴露条件决定升级优先级。
- Q3：故障注入应受控，真实道路验证需满足安全员和 ODD 要求。
- Q4：一条合理的 RCA 必须能被新数据或受控实验检验。
- Q5：需要把传感器退化与融合策略失效区分开，避免错归因。
- Q6：测试负责人提供阻断意见，放行需遵循正式授权和记录流程。
