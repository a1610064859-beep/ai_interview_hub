# 样本 05｜有课程项目的中等水平

虚构背景：完成过简单的感知与数据回放课程项目，能说清主要流程，但缺少量产测试经验。

## Q1 主回答

我是智能车辆工程专业学生。课程项目里，我们用录制的道路视频检测车道线，我负责整理雨天和逆光片段、写 Python 脚本统计漏检帧。这个项目让我发现，平均准确率高不代表边界场景安全。我希望做智驾测试，把失效场景整理成可重复验证的用例，而不是只看演示效果。

## Q2 主回答

我会先保留原始视频、软件版本、触发时间和车辆状态，避免只说“偶尔有问题”。然后与开发约定共同回放数据，尝试固定速度、光照和输入条件重复运行。若仍不能稳定复现，我会将缺陷标为未关闭，注明风险和已验证次数，请负责人决定下一轮回归优先级。

## Q3 主回答

我理解 HIL 把真实控制器放在模拟闭环里，适合重复注入传感器异常、总线丢帧等边界输入；实车道路测试则检验真实道路、天气和交通参与者对整车行为的影响。课程项目只有离线数据回放，没有真正接过 HIL 台架，所以我不会把自己的经历说成完成了台架测试。

## Q4 主回答

先保障现场安全，再记录接管时间、GPS 位置、天气、道路形态和驾驶员原因。回放接管前后的相机视频、目标列表、规划轨迹、转向指令与底盘反馈，初步判断是感知漏检、规划决策异常，还是执行偏差。不同日志先按时间戳对齐，再把疑点整理给对应模块负责人。

## Q5 主回答

暴雨会让相机图像对比度下降，激光雷达可能产生雨滴噪点，毫米波雷达可能把地面反射当成目标。大雾会削弱相机和激光雷达的远距离感知；强眩光可能导致相机过曝。融合层应检查目标是否跳变、同一目标是否被重复跟踪，以及误检和漏检是否诱发不合理制动。

## Q6 主回答

高速匝道的急转向属于高风险现象，我会先阻断“已验证可放行”的结论，锁定版本并保存 CAN、规划和底盘日志。组织开发、测试和安全负责人评审影响范围，增加相同场景及相邻速度工况回归。只有查清原因、完成修复和验证，或按正式风险流程证明有可靠控制措施，才讨论放行；不能用“只出现一次”作为依据。

## 追问补充素材

- Q1：雨天片段的漏检统计保留了帧号，可回到原视频核验。
- Q2：我会区分“未复现”和“已排除”，前者不能自动关闭缺陷。
- Q3：HIL 的优势是可控与可重复，无法完全替代实车环境。
- Q4：先确认接管信号和控制指令发生的先后，再定位模块。
- Q5：应对同一场景记录各传感器原始输出与融合目标列表。
- Q6：若原因未明且存在转向安全风险，我倾向推迟封版并形成书面风险记录。
