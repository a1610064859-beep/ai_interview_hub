# 智驾测试岗位：10 份虚构学生回答样本

用于手工走通「智驾测试」岗位的六题面试与评分报告。每个编号是一套完整的主问题回答，按 Q1→Q6 依次提交。十套内容是**虚构测试数据**，不代表真实参赛学生或真实能力提升，不应计入实测效果统计。

## 使用方法

1. 在网页选择「智驾测试」，新建一场面试；一场只使用同一个编号的 Q1–Q6。
2. 当前题目可能出现追问。先听清具体追问，再参考该文件末尾的「追问补充素材」作答；追问仍属于原题，不要提前提交下一题的答案。
3. 若测试文本模式，复制「主回答」正文即可。若测试语音模式，请自然朗读，不要把 Q 编号、标题或括号说明读出来。语音流畅度由实际录音的语速、停顿等决定，不能仅凭这些文字预设分数。
4. 每份样本单独完成六题并查看报告。可核查证据引用是否来自本次原话、缺失维度是否保留为空、整体评价是否与答案质量大体一致；不要求十份报告分数严格单调。
5. 若复用同一学生档案，成长页会把这些虚构样本视作同一人的多次训练。只用于界面联调，不要据此宣称个人能力变化。

## 题目顺序（与当前题库一致）

| 题号 | 题型 | 实际题目 |
| --- | --- | --- |
| Q1 | 通用 | 请简要介绍一下你的专业技术背景，并结合经历说明你为什么想从事智能驾驶测试工作？ |
| Q2 | 通用 | 在过去的团队项目或测试实践中，如果遇到开发人员认为“偶发不可复现”而拒绝修改的缺陷，你通常如何处理？ |
| Q3 | 专业 | 请结合实际项目，说明在智能驾驶 HIL（硬件在环）测试与实车道路测试中，两者主要的分工与测试侧重点有何不同？ |
| Q4 | 专业 | 在智驾实车路测过程中，当车辆突然发生非预期人工接管（Disengagement），你会从哪些维度采集数据并进行根本原因（RCA）初步排查？ |
| Q5 | 专业 | 请谈谈在暴雨、大雾或夜间强眩光等 Corner Case 下，毫米波雷达、激光雷达与相机多传感器融合测试时，最容易出现哪些异常表现？ |
| Q6 | 情景 | 临近量产版本封版前一天，实车回归测试中在高速匝道汇入场景下出现了一次偶发转向超调（急打方向盘），开发称仅出现一次概率极低建议放行，作为测试负责人你该如何决策？ |

## 十份样本

| 文件 | 设定 | 预期观察重点 |
| --- | --- | --- |
| [01](01-off-topic.md) | 明显跑题、缺乏安全意识 | 低专业匹配；不能因为语言自信而给高岗位素养 |
| [02](02-vague.md) | 态度积极但全是笼统表述 | 缺少过程与证据，评价应指出空泛 |
| [03](03-concept-confusion.md) | 有少量术语但概念混淆 | 应识别 HIL、传感器、放行判断错误 |
| [04](04-beginner.md) | 初学者，有课堂基础 | 能说出一些正确概念，缺乏实操链路 |
| [05](05-course-project.md) | 有课程项目，能讲基本流程 | 中等水平，仍缺定量与验证标准 |
| [06](06-intern.md) | 有台架实习，表达较清楚 | 看是否理解台架与实车分工、缺陷闭环 |
| [07](07-closure.md) | 做过故障复现与闭环 | 看 RCA、日志对齐和跨团队协作是否获识别 |
| [08](08-sensor-fusion.md) | 感知融合专项实践 | 看多传感器物理局限和误检漏检分析 |
| [09](09-integration-lead.md) | HIL 与实车联调负责人 | 看风险评审、准入准出和可核验结果 |
| [10](10-safety-lead.md) | 审慎的优秀测试负责人 | 看安全底线、证据链和不夸大结论 |

这些层级只是测试设计，**不是预先规定的模型分数**。同一编号的六题合起来代表一个人；不要把不同编号混入同一场。
