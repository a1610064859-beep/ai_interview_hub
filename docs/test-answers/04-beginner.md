# 样本 04｜初学者

虚构背景：掌握基本定义与安全直觉，但项目经验少，回答缺少具体数据和完整根因链。

## Q1 主回答

我是车辆工程大二学生，学过汽车电子和 Python 基础。在课堂实验里用脚本整理过车辆速度数据，但还没有参加完整的智驾项目。我想做测试，是因为系统能否在复杂道路上安全工作，需要有人持续发现边界问题并验证修复。

## Q2 主回答

我不会只因为缺陷偶发就关闭它。我会先记下软件版本、时间、操作步骤和环境，再请开发一起看日志。如果暂时复现不了，就保留问题并尝试扩大测试次数。不过我还不熟悉正式的缺陷分级流程。

## Q3 主回答

HIL 是把控制器接入模拟环境，适合重复测试部分输入和故障；实车是在真实道路上观察系统与环境的交互。台架更可控，实车更贴近实际。我只在课程中看过演示，还没有独立设计 HIL 用例。

## Q4 主回答

我会先确保车辆安全停靠，记录接管地点、天气、路况和安全员描述，再保存车载视频和车辆日志。我会查看接管前是否识别错了目标，以及车辆有没有发出异常控制指令；具体报文需要和负责的工程师确认。

## Q5 主回答

相机在眩光或大雾中可能看不清，激光雷达在雨雾中可能出现噪点，毫米波雷达也可能有虚警。融合结果可能误报目标或者漏掉真实目标。我会把这些情况列入场景测试，但目前不能说明每一种异常的判定阈值。

## Q6 主回答

急打方向盘可能造成事故，我不会凭一次复测没出现就直接同意放行。我会先暂停该场景的放行结论，保留日志并上报负责人，安排进一步复现和风险讨论。如果仍找不到原因，应该让安全负责人决定是否延期。

## 追问补充素材

- Q1：我的脚本仅做速度数据清洗，没有参与车控算法开发。
- Q2：至少保留原始记录，避免只凭口头描述沟通。
- Q3：台架可做可重复故障注入；道路可看真实交通参与者变化。
- Q4：接管前几秒的数据比接管后的单张截图更重要。
- Q5：误报和漏检需要分别记录，不能只报一个准确率。
- Q6：我会要求有人明确签署风险结论，但还需要学习具体准出门槛。
