# 样本 09｜HIL 与实车联调负责人

虚构背景：能把需求、台架、道路、缺陷和准出证据串起来。示例数字仅用于构造可核验的测试叙述，不是真实比赛实测数据。

## Q1 主回答

我是车辆工程专业学生，担任过校企联合智驾原型车的测试组长。我们把高速汇入、前车急减速等需求拆成场景参数，在 HIL 台架做信号故障注入，再到封闭场地验证整车响应。我负责用例与版本映射、CANoe 录制、缺陷单和回归报告。一次汇入场景中规划轨迹跳变，我用同一轨迹输入在台架重放并定位到状态切换条件。我希望继续做测试，因为安全边界需要跨模块证据，而不是演示一次成功。

## Q2 主回答

我先冻结当次软件、地图、标定与测试条件，保留视频、总线、感知和规划原始数据，并在缺陷单里写出时间窗口与预期行为。若实车偶发，就从速度、曲率、目标相对位置和时序中找共同条件，用回放或 HIL 注入验证假设。与开发共同确认复现判据，不将“这次没出现”当成修复；关闭缺陷需有根因说明、代码版本和原场景加邻近边界的回归结果。

## Q3 主回答

我们的 HIL 由真实控制器、实时车辆动力学和模拟环境输入构成，重点测状态机切换、信号丢失、总线负载、执行边界和可重复的极端参数。实车道路测试重点看传感器真实退化、道路附着、其他交通参与者和驾驶员接管等台架建模不足之处。我们用同一个场景 ID 和期望行为连通两端：台架先定位与回归，封闭场地验证安全，再在批准的 ODD 内做道路验证。台架覆盖率不能代替实车风险结论。

## Q4 主回答

我先确认安全员控制车辆并记录事件编号、版本、时间、位置、天气与 ODD 条件。提取接管前后同步窗口：原始相机、雷达和点云；融合目标与定位；规划轨迹、状态机和转向请求；底盘转角反馈、车速、横摆率及驾驶员输入。用统一时钟对齐，判断最先出现的是感知目标跳变、定位偏移、规划曲率突变还是执行器偏差；再在回放或 HIL 中复现该前置条件。初步 RCA 会标注已证实事实与待验证假设。

## Q5 主回答

暴雨会使相机受水膜影响、激光雷达出现雨滴近场回波并衰减，毫米波雷达可能有路面多径和虚警；雾天相机对比度和激光有效回波下降；夜间强眩光使图像过曝和目标框闪断。融合层可能出现目标 ID 切换、重复跟踪、位置跃迁、错误置信度或真实目标漏检，进而造成不合理制动或路径变化。我们按天气强度、目标距离和相对速度分桶，逐层保存原始检测、融合输出与整车动作，检查危险场景而非只看平均准确率。

## Q6 主回答

我会把高速汇入急转向列为阻断项，暂停该版本的安全放行签字并保护原始证据。当天召集规划、控制、底盘、测试和功能安全负责人，分析轨迹曲率、转角请求与反馈、车速和横摆率，明确潜在后果及影响范围。针对相同匝道和相邻速度、曲率工况做受控复现，查明根因后修复，跑原场景、边界场景和回归集。若封版前不能完成根因与验证，应延期或撤出相关功能范围，不能以“仅一次”替代准出证据；决策和责任人要书面留痕。

## 追问补充素材

- Q1：我负责测试证据和准出建议，算法设计由相应开发负责。
- Q2：缺陷闭环必须能从版本追到原始数据、修复提交和回归结果。
- Q3：两端共享场景编号，但分别记录台架假设和实车 ODD 限制。
- Q4：先对齐时钟并找首个异常信号，不把结果误当成原因。
- Q5：分别统计单传感器退化、融合异常和实际车辆响应。
- Q6：根因未明时风险不可用“概率低”口头豁免，需正式准出机制。
